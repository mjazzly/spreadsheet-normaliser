# The case set, written before the first run

Six cases plus two state cases. Every file is synthetic, generated by `scripts/make_cases.js` from a fixed seed, so every expected value is exact. The expected results in this folder come from the same generator run; nothing here was written by hand after a run.

## The agreed schema

Domain: monthly sales returns from six branches. Nine fields.

| Field | Type | Required | Header synonyms the code recognises |
|---|---|---|---|
| record_id | text, `AAA-0000`, unique across all files | yes | record id, ref, txn no, id, reference, record |
| branch | one of six names | yes | branch, outlet, site, location |
| sale_date | date YYYY-MM-DD | yes | sale date, transaction date, txn date, sold on, date |
| delivery_date | date YYYY-MM-DD | no | delivery date, delivered, delivered on, date |
| customer | text | yes | customer, customer name, client, buyer |
| product | one of five names | yes | product, item, sku name, goods |
| quantity | whole number, 1 or more | yes | qty, quantity, units, pcs |
| net_amount | decimal, 2 places | yes | net, net (rm), amount ex tax, before tax |
| gross_amount | decimal, 2 places | yes | gross, gross (rm), amount inc tax, after tax |

"date" sits in two synonym lists on purpose; case 4 leans on it.

## The four gates, in code

| Gate | Fires when | What happens |
|---|---|---|
| G1 two targets | the model names two candidate fields for one header, or the header is a synonym of more than one field, or two headers are proposed onto one field, or a text date column reads two ways | stop, ask, nothing from that file is written |
| G2 row count | the count after cleaning differs from the count read, beyond the rows held with a reason (a repeated record id) | stop, ask, name the rows |
| G3 type failure | a value fails its field's type after mapping | the row goes to held_rows.csv with the reason; the run continues; never coerced |
| G4 confidential | the word confidential appears in the first row of the sheet | the reader refuses; the model never sees a cell; declined in the log |

Reconciliation at the end of every pass: for every file, rows read = rows merged + rows held + rows removed by an answered gate. Declined files read zero. If the sum fails, the run fails.

Stray rows are structure, not data, so setting them aside never trips G2: a row above the header is a title row; a row with no filled cells is blank; a row whose first filled cell starts with Total, Subtotal or Grand total and which holds no record id anywhere is a totals row. Each is logged with its reason.

## Decisions taken on 30 Oct 2026, before any code

1. Files are .xlsx (via exceljs) rather than CSV: title rows, totals rows and dates as text are spreadsheet problems.
2. Domain and schema: branch sales returns, nine fields, two date fields and two money fields.
3. Case 3 carries the held n/a value (the only case that proves G3) and the two-columns-mean-one join; the checker names the file and row, so a miss stays traceable.
4. Case 4 is built on a date column. A lone "Amount" column would leave net_amount or gross_amount unsourced after the answer, and both are required, so every row would then be held. A lone "Date" with an optional delivery_date resolves cleanly after the answer.
